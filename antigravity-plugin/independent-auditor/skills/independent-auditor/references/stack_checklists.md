# 🔬 Профильные инженерные чек-листы по стекам (для `red-team-auditor`)

Подгружай и проверяй только те секции ниже, которые относятся к технологическому стеку проверяемой задачи.

## 1. Python, FastAPI, Asyncio и нативные C-расширения
- **Конкурентность `asyncio`:**
  - Нет ли повторного входа (re-entrancy deadlock) в обычный `asyncio.Lock` из той же корутины (разделены ли публичный `op()` и внутренний `_op_locked()`)?
  - Перехватывается ли `BaseException` / `asyncio.CancelledError` в критических `try ... finally`, чтобы семафоры, слоты и дочерние процессы никогда не зависали навечно?
  - Не передаётся ли один экземпляр `SQLAlchemy AsyncSession` одновременно в несколько задач `asyncio.gather` (каждая параллельная корутина обязана иметь свою сессию, либо сетевые операции выполняются вне сессии до единого `commit()`)?
- **SQLAlchemy 2.0 Async:**
  - Нет ли риска `MissingGreenlet` при синхронной сериализации ленивых связей (используется ли `.options(selectinload(...))` или проверка `inspect(obj).unloaded`)?
- **FastAPI и Uvicorn (особенно на Windows):**
  - Зарегистрированы ли статические маршруты (`/items/export`, `/items/check`) **строго выше** динамических (`/items/{item_id}`)?
  - Используется ли чистый ASGI-middleware вместо устаревшего `@app.middleware("http")` (`BaseHTTPMiddleware`), глотающего исключения и ломающего стриминг/CORS?
  - На Windows не комбинируется ли `uvicorn --reload --reload-dir` с относительным `--app-dir ..`?
- **Нативные колёса и C ABI:**
  - Согласованы ли версии взаимосвязанных C-библиотек в `requirements.txt` (например, поколение ABI у `tree-sitter` и языковых грамматик) и защищены ли не-потокобезопасные C-парсеры мьютексом `threading.Lock()`?

## 2. SQLite WAL, миграции и транзакционная целостность
- **Режим конкурентного доступа:** включены ли `PRAGMA journal_mode=WAL`, `PRAGMA synchronous=NORMAL`, `PRAGMA foreign_keys=ON` и `PRAGMA busy_timeout` на каждом соединении?
- **Составные ключи и индексы:** не затирает ли слишком узкий `PRIMARY KEY` легитимные параллельные записи (например, два разных маршрута/канала между одной парой модулей)? Есть ли покрывающие индексы под тяжёлые выборки без `TEMP B-TREE`?
- **Безопасность миграций и сбоев питания:**
  - Идемпотентны ли `ALTER TABLE` при повторном запуске приложения?
  - При двухфазной замене критических файлов на диске используется ли атомарный паттерн `temp_file -> fsync -> backup -> os.replace` с авто-восстановлением прерванных транзакций на старте?
- **Защита от SQL-инъекций:** 100% параметров передаются через `?` / `:param` (полный запрет `f-строк` и `.format()` для значений в SQL, включая `FTS5 MATCH`).

## 3. Electron, IPC-шлюзы, React 18 и TypeScript
- **Изоляция окна Electron (`BrowserWindow` / `webPreferences`):**
  - Включены ли `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`?
  - Не пробрасывается ли сырой `ipcRenderer` в `window` через `contextBridge.exposeInMainWorld` (разрешены только узкие типизированные функции-обёртки в `preload.cjs`)?
  - Прикрепляется ли секретный токен локального демона строго на стороне главного процесса (`main` / `ipcGateway.cjs`), не попадая в память рендерера?
  - При запуске `electron.exe` из `.bat` или скриптов сбрасывается ли переменная `ELECTRON_RUN_AS_NODE`?
- **Безопасность файловых операций IPC:** проверяется ли в обработчиках открытия/импорта файлов, что целевой путь лежит строго внутри разрешённого корня (`path.resolve` + проверка префикса/относительности без обхода через `..`)?
- **React & TypeScript:**
  - Нет ли бесконечных циклов запросов в `useEffect` (когда функция внутри эффекта обновляет массив/объект, стоящий в списке зависимостей этого же `useEffect`)?
  - Проходит ли строгая компиляция `tsc -b` без `any` и без передачи неподдерживаемых HTML-атрибутов в сторонние иконки (`lucide-react`)?

## 4. Безопасность периметра, криптозащита и секреты (Windows / Cross-Platform)
- **Локальные серверы (`127.0.0.1`):**
  - Слушает ли демон строго `127.0.0.1` (явный IPv4, без `0.0.0.0` и без путаницы `localhost -> ::1` на Node.js 24)?
  - Защищены ли все HTTP/WebSocket маршруты криптографическим токеном (`secrets.token_hex(32)`), чтобы открытый в браузере внешний сайт не мог прочитать локальный API?
- **Хранение ключей и запуск дочерних процессов:**
  - Не передаются ли API-ключи и пароли в открытых аргументах командной строки `subprocess` (они видны любому процессу через диспетчер задач — нужно использовать переменные окружения или временный файл ключа с правами `icacls /inheritance:r` / `0600` и занулением при выходе)?
  - При работе с Windows DPAPI (`CryptProtectData` / `CryptUnprotectData`) освобождаются ли выделенные системой буферы через `LocalFree` в блоке `finally`?
- **Симлинки и архивы:** блокируются ли симлинки и Windows NTFS Reparse Points (`FILE_ATTRIBUTE_REPARSE_POINT = 0x0400`) при сканировании папок и защита от `Zip Slip` (`Path.is_relative_to`) при распаковке архивов?
- **Защита ИИ-контура:** маскируются ли ключи (`sk-...`, `AKIA...`, `PRIVATE KEY`, токены) во всех полях (докстринги, сигнатуры с дефолтными параметрами, логи) и изолирован ли чужой текст от Prompt Injection?
